CPR Sweep Labels
----------------

There are 24 CPR configurations. Each configuration has a label:

    00, 01, 02, ..., 23

The action space is:

    3 pressure weight types
    x 2 CPR preconditioner types
    x 2 fine smoothers
    x 2 coarse smoothers
    = 24 labels

Label formula:

    label = weight_index * 8 + cprw_index * 4 + fine_index * 2 + coarse_index

Components:

    weight_type:
        0 quasiimpes
        1 trueimpes
        2 trueimpesanalytic

    preconditioner:
        0 cpr
        1 cprw

    fine smoother:
        0 paroverilu0
        1 dilu

    coarse smoother:
        0 ilu0
        1 dilu

Example:

    label 09
    = 1*8 + 0*4 + 0*2 + 1
    = trueimpes + cpr + paroverilu0 + dilu

Sweep CSV naming:

    SPE11A_09.csv

means:

    deck = SPE11A
    run used CPR config label 09


ML Training Label Logic
-----------------------

The CSV file label is the CPR configuration used for that sweep run. It is not
automatically the final ML target.

The training-label collector is:

    /Users/macbookn/activopmwkspc/cpr/opm-simulators/doc/neural_cpr/collect_sweep_labels.py

It groups rows by:

    deck, episode, newton_iter

For each grouped Newton step, it compares all available CPR configurations and
selects the one with the lowest median total_ms.

That fastest configuration becomes the supervised-learning target label.

Training sample:

    current solver/state features -> fastest CPR config label

This means the neural policy learns:

    Given the current Newton-step state, predict which CPR setup should be
    fastest.

Known Caveats
-------------

1. SPE11A neural can fail on longer runs.

   Observed error:

       Assertion failed: (isfinite(fluidState_.density(phaseIdx)))

   This happened in longer neural SPE11A runs. It also caused some Flow
   processes to remain in uninterruptible U state even after kill -9.

2. Some proposed SPE11 flags were tested and rejected.

   Unsupported by this Flow build:

       --use-best-residual=true

   The supported subset of those flags made SPE11A fail earlier, so they were
   removed from bench_norne.sh and run_spe11A_only_restart.sh.

3. Do not overwrite old output folders unless intentionally rerunning.

   Useful output folders:

       tmp_spe11_run
       tmp_spe11A_only_current

4. Performance is timing-sensitive.

   Exact wall-clock values depend on machine load, Flow build, data, and whether
   old stuck processes are consuming resources. Compare iteration counts and
   physical summaries in addition to wall time.
